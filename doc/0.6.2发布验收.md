# Phoenix Wing 0.6.2 发布验收

状态：current（已公开发布）

Owner：Phoenix Wing maintainers

适用版本：0.6.2

最后核验：2026-08-04

## 当前结论

Phoenix Wing **0.6.2 已于 2026-08-04 公开发布**。npm 身份 `phoenixwing321` 按依赖
顺序发布 11 个 scoped 包和根聚合包；12 个 Registry `latest` 与精确版本均为 0.6.2，
公开 manifests 不含 `workspace:`、`file:` 或 `link:`。本次没有 push，也没有创建或
推送 Git tag；这些 Git 操作仍由开发者手工决定。

0.6.2 是 0.6.1 的向后兼容工作台增量，包含浮层主题、Primary Panel/Section、
Primary 开关与页面 Header/MainBlock、聚合类型入口、自由文本 Output 等真实消费者
已证明的公共能力。产品 Router、权限、业务 CRUD、主题持久化和 View 内容仍由 Host
持有。

## 12 个锁步发布单元与顺序

发布必须按下列顺序逐包进入目标 cwd 执行 `pnpm publish`；core/contract 先于 adapter，
根聚合包最后。每个包的源码 manifest 都必须为 0.6.2；scoped 包必须声明
`publishConfig.access=public`，全部包必须有 `files`、`exports` 和 pnpm 发布客户端门禁。

| 4 | `@phoenix-wing/kt-codegen` | 独立 TypeScript core |

`fcstd-query` crate 与 Cargo lock 也必须一致为 0.6.2。源码中的内部依赖使用精确
`workspace:0.6.2`，pnpm pack 后必须转换为精确 Registry `0.6.2`，不得残留
`workspace:`、`file:` 或 `link:`。

`@phoenix-wing/cad-rust-source` 从本版本起按兼容冻结处理：仍作为既有发布单元完成

消费者。该边界不降低本次已列出的 Rust source 制品门禁。

## 发布前与发布后边界

Wing 的发布硬门禁只判断公共制品是否可发布，不要求在发布前完成产品仓项目适配：

- Function 的真实项目支持、列表页适配与消费回归是发布后支持项，不阻塞 0.6.2；
- Open Issue 需要正式 `phoenix-wing@0.6.2` 与 `@phoenix-wing/db-node@0.6.2`
  依赖链才能在 clean Host 中完成最终装配，这同样是发布后的消费者验收；
- 发布前不得用 `file:`、`link:`、`workspace:`、override、修改 `node_modules` 或相邻
  源码 resolver 冒充 Registry 成功。
