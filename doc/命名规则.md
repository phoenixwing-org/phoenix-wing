# 命名规则（强制）

phoenix-wing 作为发布到 npm 的公共库，所有对外暴露的名称必须加前缀，防止与使用者项目或其他第三方库冲突。

## 前缀对照表

| 类型 | 前缀 | 适用场景 | 示例 |
|------|------|----------|------|
| Vue 组件 | `Pnw`（PascalCase） | 所有 .vue 组件文件名和组件名 | `PnwAppModalOverlay` |
| CSS 类名 | `pnw-`（kebab-case） | 组件内所有 class 属性值 | `.pnw-modal-overlay` |
| 全局函数 | `pnw`（camelCase） | export 的函数 | `pnwIsTerminal` |
| Composables | `usePnw`（camelCase） | Vue composable 函数 | `usePnwDocumentTitle` |
| 全局类型 | `Pnw`（PascalCase） | export type/interface | `PnwTaskKind` |
| 全局常量 | `PNW_`（UPPER_SNAKE） | export const 常量 | `PNW_VERSION` |
| Pinia Store | `usePnw`（camelCase） | export 的 store 函数 | `usePnwAsyncTaskStore` |
| CSS 自定义属性 | `--pnw-`（kebab-case） | phoenix-wing 定义的 CSS 变量（消费项目主题变量不在此列） | `--pnw-expand-size` |

## 硬性规则

### 1. 从第一行代码就用前缀
禁止先写通用名再批量改名。批量改名已被多次证明不可靠：
- macOS `sed` 不支持 `\b` 词边界
- 动态类名 `:class="'xxx-'+var"` 不会被匹配
- 伪类选择器 `.xxx:hover` 容易漏
- JS 属性名 `store.xxxMinimized` 可能被误伤

### 2. CSS 必须 scoped
所有组件的 `<style>` 必须加 `scoped`。
CSS 类名统一用 `pnw-` 前缀，不使用短名（如 `si`, `sl`, `mt` 等易冲突）。

### 3. 消费项目的 CSS 变量不受此限
`var(--page-bg)`, `var(--text)`, `var(--border)` 等由宿主项目定义的主题变量不需要加前缀。
phoenix-wing 只定义自己所有的 `--pnw-*` 变量。

### 4. 新增导出同步更新 doc
每次新增导出后，更新 `doc/overview.md` 和 `doc/naming-checklist.md`。

## 违规示例

```ts
// ❌ 错误：无前缀，与使用者代码冲突风险
export function formatDuration(ms: number): string { ... }

// ✅ 正确
export function pnwFormatDuration(ms: number): string { ... }
```

```vue
<!-- ❌ 错误：类名太通用，全局冲突 -->
<div class="panel">

<!-- ✅ 正确 -->
<div class="pnw-panel">
```

```vue
<!-- ❌ 错误：动态类名忘加前缀 -->
:class="'card-'+t.status"

<!-- ✅ 正确 -->
:class="'pnw-card-'+t.status"
```
