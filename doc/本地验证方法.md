# 本地验证方法

在发布到 npm 之前，通过 `pnpm-workspace.yaml` 临时引用本地 `phoenix-wing` 来验证改动。

## 验证步骤

### 1. 在消费项目中临时引用本地 phoenix-wing

在 `pnpm-workspace.yaml` 中加入 `../phoenix-wing`：

```yaml
# phoenix-open-issue/pnpm-workspace.yaml
packages:
  - "packages/*"
  - "../phoenix-wing"          # ← 临时加入
```

```yaml
# phoenix-desk-tools/pnpm-workspace.yaml
packages:
  - "web-ui"
  - "packages/*"
  - "server/*"
  - "../phoenix-wing"          # ← 临时加入
```

然后安装并运行：

```bash
cd phoenix-open-issue   # 或 phoenix-desk-tools
pnpm install
pnpm dev                 # 启动验证效果
```

### 2. 验证清单

| 项目 | 验证项 |
|------|--------|
| phoenix-open-issue | Ribbon 单⾏/双⾏切换按钮是否出现、切换是否正常 |
| phoenix-open-issue | 欢迎页「返回工作台」「打开仪表盘」两个按钮 |
| phoenix-desk-tools | Ribbon 布局切换是否跟原来一致（desk-tools 自管，不受影响） |
| phoenix-desk-tools | 欢迎页功能正常 |

### 3. 类型检查（可选）

```bash
cd packages/web && npx vue-tsc --noEmit    # open-issue
cd web-ui && npx vue-tsc --noEmit          # desk-tools
```

### 4. 验证完成后恢复

确认无误后，去掉 workspace 引用并切回 npm 包：

```yaml
# 改回原样
packages:
  - "packages/*"
```

```bash
pnpm install   # 切回 npm registry 版本
```

## 为什么不用 pnpm link

`pnpm link --global` 与 pnpm workspace 协议冲突，会报 symlink 路径错误。临时改 `pnpm-workspace.yaml` 是最可靠的方式。
