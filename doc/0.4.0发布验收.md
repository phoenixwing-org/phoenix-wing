# Phoenix Wing 0.4.0 npm 发布验收

验收日期：2026-07-17

## 结论

`phoenix-wing@0.4.0` 已存在于 npm registry，但当前制品**不能被干净消费者安装**，不得把 0.4.0 标记为完整可消费发布，也不得要求 Open Issue 等 registry consumer 升级。

## 客观证据

### 聚合包存在

```text
npm view phoenix-wing@0.4.0 version
0.4.0
```

registry integrity：

```text
sha512-ZgpmOcWLKqOfIWg/ZvevwNWVdc/PldN1e7nIl3NFr+5y71npZGRfHNjbraI6yhSt8M7H78KHnXfPDQv2v8Ew3Q==
```

### 发布 manifest 含未转换的 workspace 协议

registry 返回的 dependencies：

```json
{
  "@phoenix-wing/code-core": "workspace:0.4.0",
  "@phoenix-wing/db-node": "workspace:0.4.0",
  "element-plus": "^2.0.0"
}
```

### scoped packages 尚不存在

下列 `@phoenix-wing/*@0.4.0` 查询均返回 npm `E404`：

- `code-core`
- `db-node`
- `kt-codegen`
- `cad-core`
- `cad-contracts`
- `workspace-schema`
- `cad-rust-source`

### 干净安装失败

在不包含相邻 Wing 源码的临时 npm consumer 中执行：

```bash
npm install phoenix-wing@0.4.0 --ignore-scripts
```

实际结果：

```text
npm error code EUNSUPPORTEDPROTOCOL
npm error Unsupported URL Type "workspace:": workspace:0.4.0
```

## 原因

根文档仍指导直接执行 `npm publish`。源码 manifest 使用 pnpm `workspace:` 依赖；直接 npm 发布没有执行 pnpm pack/publish 的 workspace 版本转换。现有 `verify:package-tarballs` 已能拒绝 tarball 中残留的 `workspace:`，但发布流程绕过了该门禁。

## 修复策略

npm 版本不可覆盖，因此不修补已发布的 0.4.0。下一可消费版本使用新的锁步版本，建议 `0.4.1`：

1. 所有 Wing manifests 和 `release-matrix.json` 锁步提升到 0.4.1。
2. 执行完整测试、类型检查、release matrix 和 tarball 验证。
3. 使用 `pnpm publish`，按 release matrix 顺序先发布所有 scoped packages。
4. 确认 scoped packages 可由 registry 查询和安装。
5. 最后发布聚合包 `phoenix-wing@0.4.1`。
6. 在无相邻源码的临时目录分别用 npm 与 pnpm 完成安装、导入、测试和生产构建。
7. 通过后再升级 Open Issue；可在 npm 上将聚合包 0.4.0 标记为 deprecated，说明其 workspace manifest 不可消费。

## 退出门禁

- registry 中八个发布物版本一致且均可查询。
- 任一已发布 manifest 不包含 `workspace:`、`link:`、`file:`。
- `npm install phoenix-wing@<version>` 与 `pnpm add phoenix-wing@<version>` 均通过。
- Auto-code、Desk 不依赖 committed 相邻目录 link 完成构建。
- Open Issue 使用精确 registry 版本完成测试与生产构建。

在全部门禁通过前，版本矩阵中的 0.4.0 表示源码锁步版本，不表示公共 registry 发布验收完成。
