# Phoenix Wing 0.4.3 本地发布候选验收

状态：current

Owner：Phoenix Wing maintainers

适用版本：0.4.3

最后核验：2026-07-19

## 版本结论

下一次公开 Wing 版本确定为 **0.4.3**，不另起 0.4.4：

| 层面 | 当前事实 |
| --- | --- |
| 源码与发布矩阵 | 根包、七个 scoped 包及 `release-matrix.release_version` 均为 0.4.3 |
| npm Registry | 八个包的公开 latest 均为 0.4.2 |
| 消费者 | Auto Code、Desk Tools、Open Issue 继续精确消费 Registry 0.4.2 |
| Git 标签 | 现有本地 `0.4.3` 标签早于最终修复，属于失效候选；发布前必须在最终候选提交上重新封签 |

## 候选范围

0.4.3 继续采用八个 npm 发布单元锁步版本。0.4.2 公开发布后的改进合并为以下三组：

- **Marker 与 Apply 安全性**：Kevin 控制块严格同级、禁止嵌套；下一条语法完整 Start 或 End 会终止当前打开块并恢复扫描。缺失 Start/End 分别形成 `marker.orphan-end` / `marker.missing-end` 结构化诊断，不再向后级联。`plan.canApply` 仍表示整份计划无 error；当 error 仅限这两类 Marker 问题，且其余 Target、Region、Artifact 绑定全部有效时，只投影完整安全区域，其他错误继续 fail-closed。
- **Table 分层与宿主布局**：`KtCodegenTable` 的纯 ViewModel、视觉 primitive、`contained|page` 布局、Header disclosure 和静默折叠恢复已经落地；公共 browser 入口、方法和既有事件保持兼容，高对比主题的聚焦/失焦选中态使用宿主 token。
- **跨宿主可诊断性**：Marker 诊断携带稳定错误码和源码定位；Apply 计划继续提供结构化审计，使 Auto Code 与 Desk Tools 能复用同一安全判定而各自呈现 Problems、日志和写盘结果。

其他七个包没有新增协议行为，仍因锁步发布政策同步提升版本。KtCodegen Plan、CAD native/query/provider 与 workspace Schema 主版本均未改变。

## 本地候选门禁

公开发布确认前必须同时成立：

1. 八个 `package.json`、聚合常量、内部 workspace 依赖、Rust source manifest、`fcstd-query` crate 与 `release-matrix.release_version` 均为 0.4.3。
2. `release-matrix.json` 的消费者 required 在发布前继续记录实际 Registry 0.4.2；不得提前声称消费者已经升级。
3. `pnpm verify:ci` 全绿，覆盖文档、AST 依赖方向、构建、聚合单例、版本矩阵、全 workspace 测试/类型检查、TypeScript 与 Rust tarball。
4. 干净 tarball consumer 不包含 `workspace:`、`link:` 或 `file:`，聚合 UI 仍保持 Vue/Pinia 单例。
5. 未推送的 Wing 改动归并为一个中文发布候选提交；工作树干净后创建本地注释标签 `0.4.3`，标签必须解引用到该提交。
6. 发布必须使用 pnpm；直接 `npm publish` 继续由 `prepublishOnly` 拒绝。

Marker 隔离回归采用最小化 `PNXBomAnalysis` 反面夹具：构造与析构两个连续 Start 缺 End，后续五个同级块完整。发布前必须证明结果精确为两条 `marker.missing-end`、五个 region、五个 artifact、`canApply=false`，且两个缺失块之间的手写代码不进入任何 replacement region；部分 Apply 只允许写入这五个完整区域。测试数量不在本文手写，由 `pnpm verify:ci` 的实时结果负责。

## 发布与消费顺序

获得用户公开发布确认后，固定按以下顺序执行：

1. `@phoenix-wing/code-core`
2. `@phoenix-wing/kt-codegen`
3. `@phoenix-wing/cad-contracts`
4. `@phoenix-wing/cad-core`
5. `@phoenix-wing/workspace-schema`
6. `@phoenix-wing/db-node`
7. `@phoenix-wing/cad-rust-source`
8. `phoenix-wing`

每个 scoped package 发布后必须立即查询 Registry 0.4.3；七个 scoped packages 均可查询后才允许发布聚合包。随后在无相邻 Wing 源码的临时目录完成干净安装与 smoke，再依次升级 Auto Code、Desk Tools 和 Open Issue 的精确 Registry 依赖、锁文件与消费门禁，最后独立提交发布结果和消费者矩阵。
