# Phoenix Wing 0.5.0 发布与消费验收

状态：current

Owner：Phoenix Wing maintainers

适用版本：0.5.0

最后核验：2026-07-21

## 版本结论

Wing **0.5.0** 是 0.4.3 之后的向后兼容功能版本，继续采用全部 npm 发布单元锁步版本：

- 新增 `@phoenix-wing/git-core` / `git-node`，提供 commit 群消息摘要、连续历史分析、隔离 worktree 改写与原子 ref 事务。
- 新增 `@phoenix-wing/run-core` / `run-node`，提供 Run 项目与目标模型、CAA/CMake 分类、脚本与 Task 发现及 launch plan。
- `@phoenix-wing/kt-codegen` 新增宿主无关的 Workbench UI 契约与 Web Component。
- `@phoenix-wing/cad-core` 新增 TypeScript FCStd BOM XML 解析能力。

公共协议主版本保持不变；本轮没有移除 0.4.3 API，因此使用 minor 版本 `0.5.0`，不复用已经公开发布的 `0.4.3`。

10. `@phoenix-wing/run-node`

依赖包必须先于 adapter 与聚合包发布；每发布一个包立即查询 Registry 的精确 `0.5.0`。11 个 scoped 包全部可查询后才允许发布根聚合包。

## 发布门禁

公开发布前必须同时成立：

1. 根包、11 个 scoped 包、内部 `workspace:` 依赖、Rust source manifest、`fcstd-query` crate 与 `release-matrix.release_version` 全部为 `0.5.0`。
2. 消费者矩阵在消费者实际提交前继续记录其真实 Registry 版本，不得提前声明升级。
3. `pnpm verify:ci` 全绿，覆盖文档、架构、构建、聚合输出、版本矩阵、workspace 测试与类型检查、TypeScript/Node/Rust tarball。
4. 打包后的 npm manifests 不含 `workspace:`、`link:`、`file:` 或本地路径。
5. 全部候选源码以中文提交归档；发布必须使用 pnpm，直接 `npm publish` 继续由 `prepublishOnly` 拒绝。

## 消费闭环

- Wing 0.5.0 Registry 全部可查询后，KT Auto Code 0.6.0 才能把 Git/Run 四包及既有 Wing 依赖精确闭环到 0.5.0，并重新完成 VSIX 门禁。
- Desk Tools 随后升级到 Wing 0.5.0，完成本地验证与中文提交，等待其下一次产品发布。
- Open Issue 本轮保持现有依赖版本，不修改。

## 发布回执

- Node 22.14.0 / pnpm 10.15.1 完成 `pnpm verify:ci`：54 份文档、123 个生产源文件、架构、聚合构建、全 workspace 测试与类型检查、10 个小型 TypeScript/Node 包加聚合包的干净 tarball 消费、Rust source release 编译与契约测试全部通过。
- `release-matrix` 已验证 12 个 Wing 发布物与 7 个真实消费者；Auto Code/CAD、Desk Tools 当前仍为 Registry 0.4.3，Open Issue 保持 0.4.2。
- Git Node 真实仓库集成测试在全 workspace 并行负载下采用 30 秒测试预算；Git 命令自身的 30/120 秒超时和生产算法未放宽，4 项隔离 worktree/remote/占用分支/stale HEAD 用例全部通过。
- npm Registry 发布尚未执行；发布完成后继续记录中文候选提交、逐包查询与干净 Registry 消费结果。
