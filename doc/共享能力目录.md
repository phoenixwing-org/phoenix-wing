# Phoenix Wing 共享能力目录

状态：current

Owner：Phoenix Wing maintainers

适用版本：0.5.x

最后核验：2026-07-23

本文只登记 Phoenix Wing **已经实际提供**的公共能力：存在稳定 npm export、可构建 JavaScript/`.d.ts`，并有测试或 fixture 门禁。未来候选、产品 TODO 和迁移过程不得提前登记在这里。

Desk 与 Auto 的产品需求和专有边界分别见 [Desk 产品功能归属矩阵](../../phoenix-desk-tools/doc/产品功能归属矩阵.md)与 [Auto 产品功能归属矩阵](../../kt-auto-code/doc/产品功能归属矩阵.md)。盘点过程归档在 [Phoenix AI Workspaces](../../phoenix-ai-workspaces/wing-projects/work/三库功能归属与迁移协调-2026-07-22.md)。

## 字段与维护规则

- `capabilityId` 是跨仓稳定标识。源码移动或拆文件时不改 ID；发生不兼容语义变化时由包版本/协议版本管理。
- `export` 是消费端唯一允许依赖的公开入口。产品不得通过这里列出的源码路径做运行时跨仓引用。
- `Wing 真源`、`Desk 消费`、`Auto 消费` 都是仓库相对路径，用于 AI 和开发者定位；空白表示当前没有真实消费者。
- 只有 export、类型产物和测试同时存在时才新增行；删除或改名公共能力必须先完成消费者迁移和兼容期。
- 产品矩阵可以把尚未共享的功能标成候选，但不得为候选虚构 `capabilityId`。

## 当前明确缺口

- Codegen Primary/Control/应用报告已由 Desk 与 Auto 双端消费；报告组件只维护双轴状态、筛选、运行明细和问题表，通过 `openDocument` / `openIssue` 事件把打开行为交给 Host。两端仍各自维护 Vue/VS Code Host adapter，Wing 不接管文件选择、Webview、编辑器定位、日志、剪贴板或文件事务。
- Desk 尚未消费 `pnw.code.workset`、`pnw.cad.contracts`、`pnw.cad.native-contract`、`pnw.cad.query`；`pnw.code.workset` 是 Auto 的 glob 文档协议，Desk 的 SQLite file/dir entries 不是同一存储模型。Desk 已消费 `pnw.code.caa-handoff` guard，路径授权、打开队列和工作区切换仍由 Host 负责。
- Desk runtime 当前不发布 native provider，Auto CAD 虽有 `pnw.cad.native-contract` adapter，但没有可随产品交付的 provider 制品。
- Desk 与 Auto 已双端消费 `pnw.git.node`：Desk 复用参数数组命令执行器，Auto 复用仓库读取与安全 squash adapter。Desk 的状态解析、路径授权、stage/restore/commit 事务和页面仍是产品逻辑；Desk 尚无 `pnw.git.core` 的 commit-organize 产品入口。Wing Workbench 壳也没有实际产品消费者。

## 增删检查

新增目录项前必须回答：

1. 对应的公开 export 是什么，能否从干净 consumer 安装？
2. JavaScript、`.d.ts`、测试/fixture 是否一同发布？
3. 哪个产品路径已经真实消费，还是只是未来候选？
4. 是否误把 VS Code、Tauri、Hono、Vue 或 Node 文件 IO 带入纯 core？
5. 产品矩阵是否引用了同一个 `capabilityId`，并保持产品专有责任不变？
