# 三库共享核心整改计划

> 适用仓库：`phoenix-wing`、`phoenix-desk-tools`、`kt-auto-code`。本文是共享核心边界、接口、版本和跨端验收的权威计划；算法语义、锁定规则与回归契约以 [C++成员排序算法规范.md](C++成员排序算法规范.md) 为唯一权威文档。各产品仓库仅维护自己的接入计划。

## 总目标

在 Apache-2.0、权利人“上海锟钛”一致的前提下，将可复用的 C++ 成员排序与 CAA 领域能力抽为 Wing 的纯 TypeScript core。Desk Tools 和 KT Auto Code 只保留各自宿主适配与界面：前者保留 Vue/Tauri 的复杂编辑，后者在编辑区结果 View 提供预览、选择、diff 和确认写回。

## 非目标

- 不把 Python 排序实现、FastAPI、Vue、Element Plus、Pinia、Tauri、`vscode` 或 Node `fs` 放进 core。
- 不将完整 CAA Vue 编辑器嵌入 VS Code Webview。
- 不复制同一份排序/CAA 规则到两个产品仓库。

## 包与依赖边界

```text
phoenix-wing
  code-core/       C++ 解析、排序、TextEdit、诊断
  catdlg-core/     CAA IR、解析、emit、patch、merge、校验
  file-core/       可选：编码与字节/文本边界

phoenix-desk-tools  Node/Tauri IO adapter + Vue/Tauri 复杂预览
kt-auto-code        VS Code IO adapter + 编辑区结果 View
```

core 接受文本、IR、选项和抽象诊断；文件读写由注入 adapter 负责。公共导出遵守 `AGENTS.md` 前缀规则：函数 `pnw*`、类型 `Pnw*`、常量 `PNW_*`。

## 里程碑与时间盒

| 阶段 | 时间盒 | 交付与退出条件 |
| --- | --- | --- |
| R0 基线整改 | **1 小时** | 三库 Apache-2.0/权利人一致；文档入口完成；引擎、fixture、依赖清单明确 |
| R1 排序 core | 0.5–1 天 | `code-core` 导出稳定 API；现有 desk-tools golden 输出等价 |
| R2 双端预览 | 0.5–1 天 | desk-tools 与插件均消费同一 core；插件在编辑区 View 预览而非 Side Bar 表格 |
| R3 CAA core | 1–2 天 | `catdlg-core` 迁入、browser/node adapter 边界和 fixture 契约固定 |

因此，**1 小时是正确的 R0 目标**，但不是“抽包并交付预览”的总工期。R1/R2 是第一个能实际使用的函数排序增量，建议连续安排 1–2 个开发日。

## 公共排序契约（R1）

```ts
export interface PnwReorderInput {
  uri: string;
  text: string;
  encoding: "utf8" | "utf8-bom" | "ascii" | "gbk" | "unknown";
}

export interface PnwReorderResult {
  changed: boolean;
  text: string;
  edits: readonly PnwTextEdit[];
  diagnostics: readonly PnwDiagnostic[];
  lockedRanges: readonly PnwTextRange[];
}
```

API 命名在实施前可调整，但必须保留：纯文本输入、可序列化编辑/诊断、无宿主对象、仅在内容变化时返回写回候选。

## 排序依赖清单（R0 结论）

| 来源 | 归属 | 处理 |

## 验收

1. 同一 fixture 在 desk-tools 与 VS Code Host 得到相同 `text`、`edits` 与 diagnostics。
2. 用户在任一产品看到 preview 后才可写回；写回前检查文件指纹，冲突不覆盖。
3. 共享包不依赖 UI 框架或宿主 API；产品层不复制算法。
4. 三库发布物和仓库元数据均声明 Apache-2.0 与同一权利人。
