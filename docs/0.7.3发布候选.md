## 2. 候选能力边界

- `PnwCombo` 管理受控候选、删除和清空意图；真实持久化仍由 Host 负责。
- 清理能力坚持 preview/execute 两阶段、冻结路径身份、取消协作、符号链接与文件系统根保护；
  对话框只负责交互，不绕过 Node provider 的执行前复验。
- Git 提交图仍是只读分页。`date-order` 让并行分支按提交者时间交错，同时保证子提交先于父提交；
  旧 v1 cursor 不可续读，Host 必须清空旧页并重开。
- Codegen 继续由 Host 持有文件、草稿和写盘授权；Wing 只提供纯 TS 计划、表格与 Primary 交互。
- 根 Header 调整不改变 Host 的 View 路由、关闭、停靠或持久化责任。

## 3. 本地候选门禁

- [x] `pnpm test:workspace`；
- [x] `pnpm -r --include-workspace-root --if-present typecheck`；
- [x] `pnpm verify:release-matrix`；
- [x] `PNW_VERIFY_OFFLINE=1 pnpm verify:package-tarballs`；
- [x] `pnpm verify:cad-rust-tarball`；
- [x] `pnpm docs:check`、`pnpm verify:architecture`、根 build 与 aggregate dist；
- [x] 确认生成 tarball 不含 `workspace:`、`link:` 或 `file:`，且六个候选版本/入口可从隔离 consumer 加载。

门禁失败时不得发布。测试和打包只能证明本地候选，不等于 Registry 已发布。

## 4. 消费者与发布边界

- Auto Code、Auto CAD 及其他消费者的 manifest/lockfile 不随本次 Wing 本地准备自动更新；
- Registry 发布后，消费者才可按各自任务精确升级并执行干净安装、类型、构建和 Host 回归；
- 本次授权只包含 Wing 0.7.3 版本准备与本地 Git commit，不包含 npm publish、push、tag；
- 发布前必须重新核对分支、版本、状态、发布集合及 Registry exact 版本是否可用。
