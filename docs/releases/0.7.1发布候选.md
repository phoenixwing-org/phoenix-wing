## 2. 公共能力与兼容边界

### 2.1 通用 Navigation Tree

- 稳定消费入口保持 `@phoenix-wing/code-core/ui` 与 `@phoenix-wing/code-core/ui/model`；
- class / tag / model 分别为 `PnwNavigationTreeView`、`<pnw-navigation-tree>`、
  `PnwNavigationTreeModel / PnwNavigationTreeNode`；
- 数据递归支持多层，提供受控 icon key、文本安全、ARIA tree、漫游焦点、键盘操作、窄宽滚动
  以及 VS Code 风格 light/dark/system 状态；
- Host 继续持有 `expandedNodeIds`。含子节点的整行单击只派发 toggle 意图，不在组件内保存
  业务偏好；
- 双击去重只对同一 DOM 行实例 best-effort。Host 若在第一次 click 后同步重建 Tree/行，第二次
  click 可能重新成为 `detail=1`；稳定推荐手势仍是整行单击，Wing 不跨 Host 生命周期保存
  短时交互状态。

完整契约见[《Pnw 通用 Navigation Tree Web Component》](../Pnw通用NavigationTreeWebComponent.md)
与[《Pnw 通用 Web Component 分层与命名规则》](../Pnw通用WebComponent分层与命名规则.md)。

### 2.2 Git 提交图轻量分页

- `pnwReadGitCommitGraphPage` 默认首页 5 条，可按不透明 cursor 继续 1 条或 5 条；
- 支持 HEAD、所有本地分支以及可选 tag scope，返回 decorations、merge parents 与纯数据
  `graphRows`；
- 每页只执行一次 NUL-safe、`--topo-order`、`limit+1` 的有界 `git log`，不读取全仓库快照、
  不 checkout、不逐 commit spawn；
- `expectedHeadOid`、stale HEAD、AbortSignal 与跨页 lane continuation 均为强契约；
- SVG、颜色、行选择和产品确认 UI 不进入 Core/Node adapter。

完整契约见[《Git 提交图轻量分页与拓扑车道》](../Git提交图轻量分页与拓扑车道.md)。

### 2.3 Codegen Primary 连续 Section

`@phoenix-wing/kt-codegen/ui` 的 Primary 顶层 Section 使用 `gap: 0`、无圆角、无左右卡片
边框，只以纵向分隔线连续排列；标题、列表、表单和按钮仍保留自身 2–8px 内边距。Host 不应
穿透 Shadow DOM 重写面板横向间距。

  stale HEAD、scope、abort 测试通过；tarball clean consumer runtime smoke 通过；
- Codegen Primary 的 Shadow DOM 契约、包测试、类型、构建通过；真实扩展宿主已人工确认深色
  侧栏与其他连续 Section 接边一致，`gap=0`、无圆角/左右卡片边框、上下分隔线正确；

## 5. 消费者回归与非阻断边界

- Navigation Tree 与 Codegen 已取得真实扩展宿主的本地 sibling 自动回归；Codegen 深色人工
  视觉已通过；浅色与窄屏人工点检可在发布前补充，但不能以文档推断代替实测；
- Git Graph 的“首 5 / 下 1 / 下 5”、多分支/merge 真实 UI 与 stale HEAD 恢复仍待消费者
  人工回归。若把它列为本轮对外主能力，则该项是发布前消费者门禁；若本轮仅发布底层只读
  API，也必须在发布回执中明确 UI 回归后置，不得写成已通过；
- 双击跨同步 DOM 重建的 toggle 去重不作为 0.6.4 API 承诺；产品应采用整行单击，或在需要
  双击时保持同一 element 实例/自行保存跨重建短时状态；
- 本轮不整理现有三个 Web Component 的物理目录，不新增 `/ui/elements` subpath，也不把 Vue
  wrapper、VS Code API、产品 DTO 或任意 HTML/SVG 输入带入 `code-core`。

## 6. 发布顺序与回执要求

按依赖顺序在每个目标 package 的 cwd 执行 pnpm 发布：

1. `@phoenix-wing/code-core@0.6.4`、`@phoenix-wing/git-core@0.6.4`、
   `@phoenix-wing/kt-codegen@0.6.4`；
2. Registry 可查询 `git-core@0.6.4` 后发布 `@phoenix-wing/git-node@0.6.4`；
3. Registry 可查询 `code-core@0.6.4` 后发布根 `phoenix-wing@0.7.1`；
4. 每包分别核对 exact/latest、公开 manifest、integrity/shasum；
5. 在无相邻 Wing 源码的 clean Registry consumer 重跑入口、运行时和生产构建；
6. 发布回执必须记录版本、顺序、命令、Registry 证据、clean consumer 结果与未完成的消费者
   人工项，不得用本地 sibling 成功冒充 Registry 成功。

不得使用 `npm publish`、`pnpm --dir ... publish` 或 `pnpm -r publish`；详细命令与 token
要求见[《发布配置步骤》](../发布配置步骤.md)。
