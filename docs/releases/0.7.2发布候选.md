# Phoenix Wing 0.7.2 发布候选与验收

状态：current（待发布）

Owner：Phoenix Wing maintainers

适用版本：根包 0.7.2；scoped packages 按独立版本矩阵

最后核验：2026-08-28

## 1. 发布集合

本轮只有根 Vue/UI 聚合包发生变化：

| 发布单元 | 候选版本 | 变化 |
| --- | --- | --- |
| `phoenix-wing` | `0.7.2` | 统一完整 View presentation context、非模态 View Dialog Host、浮窗动作与多窗口栈 |

11 个 `@phoenix-wing/*` scoped packages 没有源码、公开 API、制品或内部依赖变化，继续保持
`release-matrix.json` 中的独立版本，不得被根版本带动为空的 `0.7.2`。

## 2. 多消费者统一界面边界

0.7.2 的目标不是让每个产品复制一套浮窗，而是把共同机制收进 Wing：

- 完整路由 View 由 Host 持有 owner Tab、Router、KeepAlive、dirty guard 与 presentation
  record；业务页面只使用 `PnwPageHeader` 和最小 presentation context；
- `pnwProvideViewPresentationContext()` / `usePnwViewPresentationContext()` 让 Header 获得
  浮出与收回命令，消费者不得再自建 Portal、Teleport、浮窗栈或重复按钮；
- 独立检查器、选择器和小型编辑器使用 `pnwCreateViewDialogHost()`、
  `PnwViewDialogHost` 与白名单 renderer；请求 props 必须是有限 JSON 可序列化值；
- `PnwDockableToolWindow` 继续承担可停靠工具；不得把 Tool、完整 View 与 View Dialog
  三种关闭语义混为一套；
- 恢复推荐尺寸、收回到 Editor、关闭 View 使用不同图标、Tooltip 与 ARIA。无关闭动作时
  顺序为“恢复 → 收回”，有关闭动作时为“恢复 → 收回 → 关闭”。

产品仍保留业务 Store、权限、路由、菜单、保存确认和领域 UI；Wing 只统一宿主机制与交互
契约，避免消费者以 CSS、图标覆盖或本地 singleton 修补宿主缺口。

## 3. 发布制品硬门禁

- [x] `pnpm build` 与 `pnpm verify:aggregate-dist`；
- [x] 聚合制品强制包含 `PnwViewDialogHost`、`usePnwViewDialogHost`、
  `usePnwViewPresentationContext` 及其声明文件；纯类型 `PnwViewDialogHost` 不产生空 `.js`；
- [x] 独立临时 npm cache 下的 `pnpm verify:package-tarballs`；干净 consumer 同时验证根入口、
  兼容子路径、Vue singleton、Dialog Host identity 与生产 Vite 构建；
- [x] 聚焦测试、workspace typecheck、聚合 build、release matrix 与 Rust tarball在当前候选树
  的前置联调中通过；
- [x] 使用 Node 22.23.1 在当前候选树重跑 `PNW_VERIFY_OFFLINE=1 pnpm verify:ci`；使用独立
  临时 npm cache，未修改用户全局 cache；
- [ ] Registry 发布后，在没有相邻 Wing 源码的 Admin/其他真实消费者中精确安装
  `phoenix-wing@0.7.2`，再跑类型、生产构建与浏览器回归。

## 4. 消费者迁移顺序

1. Phoenix Admin Host 先提供唯一完整 View wrapper、全局 Dialog Host 与 context；
2. 已接入的 Phoenix 插件删除自己的 route Portal/record，只保留 Header、业务内容和保存守卫；
3. 桌面/Web 工具保留自己的 workspace/tab 生命周期，仅增加薄 Host adapter；
4. 已稳定使用 Wing Portal 的消费者先做 0.7.2 回归，不为了“统一”重写已验证的业务 adapter；
5. 最后扩展到 Cool 原生 View；这属于后续可行性研究，不进入 0.7.2 发布承诺。

消费者验收至少覆盖：默认恢复按钮禁用、resize 后启用且恢复后再次禁用，收回/关闭图标与
语义不同，多 View/Dialog/Tool 的焦点和 Escape 只作用于 active 窗口，关闭 owner Tab 能
恰好清理所属 Dialog，浏览器 console 无新增错误。

## 5. 品牌与后台设定边界

品牌插件和工作台标题/Logo/副标题属于 Host-owned 快照与配置消费，不进入 Wing 0.7.2。
后续应复用 Wing 的布局组件呈现，但活动品牌选择、资源 SHA、匿名登录快照、工作台快照、
原子缓存和安全回退仍由 Admin Host 负责。必须先完成纯 Host、活动品牌、损坏快照、停用与
卸载矩阵，再把结果列为消费者回归证据，不能用本地 DOM 投影冒充 Host 快照。

## 6. 发布边界

公开 Registry 当前 `latest` 为 `phoenix-wing@0.7.1`。0.7.2 尚未发布；本地 sibling 验证不
等于 Registry 验证。只有用户明确授权后，才允许在仓库根目录执行：

```bash
pnpm publish --access public --no-git-checks
```

不得发布未变化的 scoped packages，不得使用 `npm publish`，不得自动 push、tag 或发布。
