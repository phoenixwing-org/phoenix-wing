# 0.8.1 发布目标与候选验收

状态：2026-10-20 本地候选已完成下述源码、制品与限定隐私验收，未发布；完整发布仍需独立授权与 Registry 回执。0.8.0 已于 2026-10-07 正式发布，回执见 [0.8.0 发布验收](0.8.0发布候选.md)。

## 目标范围

以已发布 0.8.0 为基线，本轮按实际运行源码与公开接口变化准备以下三个独立发布单元，不因版本矩阵共有 11 包而全部升版：

| 发布单元 | 已发布基线 → 本地候选 | 变化范围 |
| --- | --- | --- |
| `phoenix-wing` | 0.8.0 → 0.8.1 | Workspace、模态、Portal/Header、Card/滚动及 Primary 动态宽度目标 |
| `@phoenix-wing/code-core` | 0.6.7 → 0.6.8 | C++ 重排安全、可选函数文档与 include 分组、结果行交互 |
| `@phoenix-wing/run-node` | 0.6.4 → 0.6.5 | 插件数据保护、Git reset 冲突拒绝及非递归子模块恢复 |

根 manifest 与 `PNW_VERSION` 为 0.8.1，根内部依赖精确指向 `code-core@0.6.8`，发布矩阵与 lockfile 同步。其余八个独立子包不变；Codegen 规则仍为 1.0.2，workspace Schema v13 与 CAD native/query/provider v1 不变。Rust CAD 退役已属于 0.8.0，不重复作为本轮新功能。本地版本声明不代表 Registry 已发布。

- Workspace 最小一致性修复：prepare 抛错的参与者纳入回滚，异步边界及时检查取消，Host close 接收 transition signal。
- 回滚使用独立未取消 signal；清理或恢复失败返回 rejected，不被 cancelled/superseded 掩盖。
- 可选 host.recover(context) 由使用方恢复当前资源并核验身份；Wing 等待恢复结束后运行新请求，不自动重开工作空间。保存、释放、重开及 UUID/canonical root 核验继续由使用方负责。
- 每个 Portal 按稳定动作 ID 解析唯一所有者，支持简化 Header 和旧显式调用。
- Card 标题与操作区适配窄容器，增加独立示例；窄屏工作台正文允许纵向滚动链传递。
- Code Core 保守重排补强、可选函数文档与 include 分组公开接口，以及保留原扫描 revision 的结果行操作；不把文本算法验收扩张为目标 C++/CAA 工具链验收。
- Primary 最大宽度改为排除 Tree 后当前 View 的 60%，同时保留既有 Editor/Secondary 空间预算；不再固定 560px。保存偏好与当前可见尺寸分离，容器缩小时不覆盖偏好，恢复后重新显示；鼠标、键盘和 aria 上限共用同一规则。示例目录通过公共 CSS 变量跟随 Primary，不改独立 Tree 的默认宽度。

本轮以本地归档 `fc0c45e32fdcd1a9facffcbfd1a746c6b1add8fa` 为基线归档 Primary 修复、版本准备和隐私整改。此前 Workspace/UI/嵌套模态节点 933dfab、清理安全节点 37405a3，以及更早的 c29499a、da9d551 只保留历史来源含义。消费者使用 Registry 0.8.0、code-core 0.6.7 或 run-node 0.6.4 不会自动获得本轮修改。

## 清理安全与发布点检（2026-10-12，历史候选验证）

- 默认递归/Git 清理保留 `.phoenix`（不区分大小写），父目录拆分为安全子目标；已跟踪插件数据有变化时拒绝强制恢复。规则直属清理仍只接受明确的项目规则授权，不新增默认删除插件数据的界面选项。
- 补充修复：HEAD 的文件/链接路径可能与当前含 `.phoenix` 的未跟踪目录发生类型冲突，`reset --hard` 会先删目录，不能只依赖 clean 排除规则。现在预览和执行前复验均拒绝这种覆盖，保留插件数据及其他已跟踪改动；执行前才出现的冲突也须在 reset 前拒绝。
- reset 显式使用 `--no-recurse-submodules`，不继承本机 `submodule.recurse=true`；只恢复本次选定仓库，不自动进入未预览的子模块恢复已跟踪内容。子模块如需清理，应作为独立目标重新预览。
- 定向回归覆盖小写/大写插件目录、带空格和路径元字符的祖先、暂存区删除、预览后新增保护目录、符号链接恢复路径、不跟随外部目录链接，以及名称前缀相似但不冲突的安全清理；真实临时子模块另验证递归配置不绕过保护。仅使用专用临时 Git 仓库，不执行用户项目清理；Windows 实机待测。
- rebase 后原门禁为全 workspace 964 项测试；本轮最终修复重新运行 `pnpm verify:ci`，972 项通过（run-node 3 个文件、63 项）。构建/类型、文档/架构/当前版本矩阵与 1 聚合 + 10 小包的临时 tarball 隔离安装通过；不是升版后的正式发布验收。

## 原 working 开发记录

以下记录迁自 0.7.6 发布文档，仅保留早期开发验证范围；不是本次合并后的浏览器验收，也不改变 0.7.6 或 0.8.0 的正式发布回执。

### 框架动作唯一所有权

- 以稳定 `pnw.view.detach` / `pnw.view.reattach` ID 在每个 Portal 内注册并解析动作所有者；显式旧 Header 不再和浮窗 chrome 重复收回，简化 Header 无需判断 mode。
- 浏览器 `/page-layout.html` 的简化与旧显式调用均验证浮出后仅一个收回 ID；状态回迁可操作。定向测试覆盖独立 View、卸载重挂与业务插槽更新；不使用全局 DOM 扫描或按钮文字去重。
- Card 长路径 select 与按钮在实际 340px、240px 卡片中逐个 bounding rect 检查均未越界，actions 点击保持展开；无需内部样式覆盖。

### Card 原生样式

- 原 card 只有上下直线且依赖旧主题变量；改为 Wing 主题 token 与 fallback，原生提供完整 1px 外框、8px 圆角、至少 40px 标题、展开分隔线、正文 padding/gap 与窄屏 actions 换行。strip 保持不变。
- `/?example=cards` 通过公共样式入口验证相邻卡片、表格、图表；明暗主题、展开折叠、actions 不触发折叠、240px 窄容器无横向溢出已点检。示例仅设置宿主流式布局和内容样式，不补组件外观。
- Card/Primary 行为测试 8 项、根包构建、示例类型检查与文档门禁通过。消费更新构建后撤除旧外观补丁，不要求调用方恢复内部选择器覆盖；本项未发布。

### 窄屏滚动链回归

- 窄屏工作台内容区仅对 page 模式 View、可滚动 SidebarBlock 与 PageLayout 正文放开纵向滚动链；外层仍保留 containment，不全局覆盖浮窗或横向滚动。
- 本地示例在 800×650 视口验证：Primary 与普通正文可向外层传递滚轮；page 模式内部触底后继续滚轮，外层继续滚动。
- 浮出后正文仍为 `overscroll-behavior-y: contain`，滚轮不推动背后的工作台；1200×650 宽屏正文仍独立滚动。
- 定向滚动边界及 Header 测试 9 项通过，根包构建通过。此项为 working 本地构建验收，不代表 Registry 已发布或完整发布门禁完成。
- Header 的 Teleport 根不承诺 DOM attrs 自动透传；标准文档已说明，示例移除冗余 Header class 绑定。
- Primary 封装补强：对 Primary region 内真实 SidebarBlock 根使用更高优先级的限定选择器，编译 scoped CSS 后的优先级回归通过，避免基础 SidebarBlock 样式后加载时覆盖。682px 示例中真实 PnwPrimaryPanel 正文高度与 scrollHeight 均为 428px、无内部溢出，computed 纵向策略为 auto；属性 dl 上滚轮令外层从 0 滚至 112px。新增后滚动测试共 2 项通过，构建通过。
