# Phoenix Wing 独立版本发布规则

状态：current

Owner：Phoenix Wing maintainers

适用版本：0.6.4+

最后核验：2026-08-21

## 结论

从 0.6.4 开始，Phoenix Wing 默认采用**按包独立版本**，不再因为一个包的小改动把
全部发布单元统一升版。0.6.3 是最后一个 12 包统一锁步发布的基线。

`release-matrix.json` 为每个发布单元分别记录精确版本；根包的 `PNW_VERSION` 只表示
`phoenix-wing` Vue/UI 聚合包版本，不代表所有 `@phoenix-wing/*` 子包版本。

## 何时升级哪个包

| 变化 | 版本处理 |
| --- | --- |
| 只改消费者插件或产品业务 | 只升级消费者；Wing 不升版 |
| 只改一个独立 Wing 包 | 只升级该包 |
| 上层包需要消费下层包的新 API | 下层包先升级；上层包更新精确依赖并同时升级 |
| 上层包仍可继续使用旧下层 API | 上层包不升级，依赖保持旧精确版本 |
| 只改 Vue 工作台组件 | 只升级根 `phoenix-wing`；稳定 Core/Node/Rust 包不动 |
| 跨包不兼容协议或明确发布列车 | 经单独决策后才允许锁步升级相关发布组 |

版本号遵守每个包自己的 SemVer。没有源码、公开 API、制品或依赖变化的包不得为了
“看起来整齐”产生空 patch。兼容冻结的 `cad-rust-source` 在重新明确维护和消费前只做
必要的安全、协议或制品修复，不跟随 UI 发布。

## 依赖与矩阵

内部依赖继续使用精确 `workspace:<version>`，其中版本必须等于**被依赖包**在矩阵中
声明的版本。pnpm pack 后必须转换成同一精确 Registry 版本，不得残留 `workspace:`、
`file:` 或 `link:`。

例如根 UI 包为 0.6.4、两个稳定依赖仍为 0.6.3：

```json
{
  "name": "phoenix-wing",
  "version": "0.6.4",
  "dependencies": {
    "@phoenix-wing/code-core": "workspace:0.6.3",
    "@phoenix-wing/db-node": "workspace:0.6.3"
  }
}
```

`pnpm verify:release-matrix` 必须检查每个 manifest 对应自己的矩阵版本、内部依赖对应
被依赖包版本、根 `PNW_VERSION` 与根包一致，以及 Rust source 的 npm/Cargo 身份只在
其自身版本内一致。

## 发布集合与顺序

每次候选必须列出“实际发布集合”。发布前用 Git diff、公开 API/制品变化和内部依赖图
确定集合；不得直接把矩阵中的全部包视为待发布。

1. 先发布集合中的下层 Core/contract；
2. 精确版本可查询后，再发布集合中依赖它的 adapter；
3. 根包只有发生变化时才发布，并在其本轮依赖包可查询后发布；
4. 每个已发布包分别核验 exact/latest；
5. 在无相邻源码的 clean consumer 中只安装本次发布集合及所需 peers；
6. 未变化包只验证依赖可解析，不重复发布。

发布仍只允许在目标包 cwd 执行 `pnpm publish --access public --no-git-checks`。AI 不因
版本已准备就自动 publish、push 或创建 tag；这些动作继续等待开发者明确授权。

## 0.6.4 应用

当前 0.6.4 候选只修改 `PnwPrimarySection`，属于根 Vue/UI 聚合包：

- `phoenix-wing`: 0.6.3 → 0.6.4；
- 11 个 scoped packages：保持已发布的 0.6.3；
- 根依赖 `code-core` / `db-node`：保持精确 0.6.3；
- 本轮实际发布集合仅为 `phoenix-wing@0.6.4`。

## 0.7.1 应用

0.7.1 已发布，发布集合同时包含根聚合包和四个实际发生变化的 scoped 包：

- `phoenix-wing@0.7.1`：更新聚合版本，并把 `code-core` 精确内部依赖提升到 0.6.4；
- `@phoenix-wing/code-core@0.6.4`：新增通用 Navigation Tree model 与 Web Component；
- `@phoenix-wing/git-core@0.6.4`：新增纯数据 commit graph lane 投影；
- `@phoenix-wing/git-node@0.6.4`：新增轻量 commit graph 分页，并精确依赖 `git-core@0.6.4`；
- `@phoenix-wing/kt-codegen@0.6.4`：统一 Primary 顶层连续 Section 视觉。

其余七个 scoped 包没有源码、公开 API、制品或依赖变化，继续保持 0.6.3。发布顺序为
`code-core / git-core / kt-codegen`（彼此可独立）→ `git-node` → 根 `phoenix-wing`；不得重复
发布未变化包，也不得把根版本 0.7.1 误套到 scoped packages。

## 0.7.2 应用

0.7.2 只修改根 Vue/UI 聚合包，新增统一完整 View presentation context、非模态 View
Dialog Host 与浮窗动作修正：

- `phoenix-wing`: 0.7.1 → 0.7.2；
- 11 个 scoped packages：保持各自在 `release-matrix.json` 中的 0.6.3/0.6.4；
- 根包继续精确依赖已发布的 `code-core@0.6.4` 与 `db-node@0.6.3`；
- 本轮实际发布集合仅为 `phoenix-wing@0.7.2`。

## 0.7.3 应用

0.7.3 候选包含根工作台、通用 Code UI、Git Node、Run Core/Node 与 Codegen 的真实变化，
继续按包独立提升 patch：

- `phoenix-wing@0.7.3`：统一三段式 View Header 动作收纳，并把 `code-core` 精确内部依赖提升到 0.6.5；
- `@phoenix-wing/code-core@0.6.5`：增加可管理 Combo 与统一清理对话框；
- `@phoenix-wing/git-node@0.6.5`：提交图改用 `date-order`，游标 schema 提升到 v2；
- `@phoenix-wing/run-core@0.6.4`：增加跨宿主清理规则解析；
- `@phoenix-wing/run-node@0.6.4`：增加冻结预览、递归产物、Git 未跟踪与强制清理执行，并精确依赖 `run-core@0.6.4`；
- `@phoenix-wing/kt-codegen@0.6.5`：统一 Primary 文字操作、运行锁和 CAA/参数表交互。

`git-core`、CAD contracts/core/Rust source、workspace schema 与 db-node 没有源码、公开 API、
制品或依赖变化，保持矩阵中的既有版本。发布顺序为
`code-core / run-core / kt-codegen` → `git-node / run-node` → 根 `phoenix-wing`。
