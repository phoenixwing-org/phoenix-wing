# C++ 成员排序算法规范

> **权威位置**：`phoenix-wing`。本文件描述 `packages/code-core/src/` 的排序语义、保护边界与回归契约。
> 消费方只能调用此 core，不复制或改写排序规则。
> 产品界面、文件选择、编码读写、Git 操作与写盘确认属于各自宿主，见本文“宿主契约”。

## 1. 实现与公开接口

| 文件 | 接口 | 职责 |
| --- | --- | --- |
| `packages/code-core/src/pnwReorderCpp.ts` | `pnwReorderCppText(text, fileStem)` | `.cpp/.cc/.cxx` 中同一类的成员实现排序与分隔线整理 |
| `packages/code-core/src/pnwReorderHeader.ts` | `pnwReorderHeaderText(text, options)` | `.h/.hpp/.hh` 类声明、访问区与锁定段处理 |
| `packages/code-core/src/pnwReorderHeader.ts` | `pnwFindLockedRegions` / `pnwExtractLockedRegionContents` | 锁定段发现与回归断言 |
| `packages/code-core/src/pnwDocumentCpp.ts` | `pnwDocumentCppFunctionsText(text, { headerText? })` | 独立补齐可识别函数的空白文档，不移动定义 |
| `packages/code-core/src/pnwReorderSafety.ts` | `PNW_REORDER_SAFETY_VERSION` | 宿主可写入能力契约；当前候选为 `1`，与包版本、代码生成规则版本独立 |

core 只接受文本并返回文本、`changed` 和警告（header 的 `warnings`；source 新增可选 `warnings`）；不读取文件、不写文件、不依赖 Git、VS Code、Node `fs`、Vue 或 Tauri。

## 2. 通用安全约束

- 保留原文件换行风格：LF、CRLF、CR 均不被统一成另一种风格。
- 排序必须幂等：同一输入连续执行两次，第二次 `changed === false`。
- 代码位置识别跳过注释和字符串，避免把注释或字符串中的 `Class::method` 当成声明/定义。
- 无法安全识别的结构宁可保留源顺序，并通过 `warnings` 暴露风险；不得猜测后写盘。
- 未闭合、多余结束或同类标签配对错误的保护标记，必须在重建之前阻止整份文件。Header 旧扫描器尚不能安全重建 raw string，当前遇到真实 raw literal 整份保留并警告；不得把原始字符串内的括号、引号或假标记当成结构。
- `GBK`、UTF-8 BOM 与文件字节写回不是 core 的职责：宿主须在调用前解码，并在写回时保持原编码/BOM。

## 3. `.cpp` 成员实现排序

### 3.1 作用范围与安全边界

1. 先从类限定实现中识别目标类；优先使用 `fileStem`，否则选择出现次数最多的首字母大写限定类名。
2. 没有可识别构造函数时不改写文件。这是为避免生成代码、Wizard 区和非典型实现被错误重排的保守边界。
3. 只重排类外成员定义；函数体内对 `Class::method()` 的调用不提取为独立块。
4. 函数前连续注释、分行返回类型与函数体随同一个块移动；函数之间的空白行被规范化。
5. 2026-09-27 安全增量：函数间的非成员代码（CAA TIE 注册、宏、自由函数、namespace 边界等）以及排序范围内的预处理指令不能丢弃或跨越；遇到这些结构保留整份 source 并返回警告；下述明确支持的文件级 pragma 折叠区、TIE 注册对与完整函数体内部条件编译除外。
6. 结构扫描屏蔽普通/原始字符串及注释，避免其中的大括号或伪成员名改变函数边界。重建后再次比较所有锁定段；不一致则拒绝输出并保留原文。
7. 分行返回类型必须先纳入函数块，再向前归属注释和分隔线。首个函数的说明随函数移动，末尾独立说明留在末尾；函数行尾说明不得复制成下一函数的分隔线。无法归属的函数间普通说明触发整份 source 跳过。
8. 2026-10-12：紧邻函数签名（含分行返回类型）的“纯分隔线 / 连续 `//` 说明 / 纯分隔线”按一个完整函数说明框处理，至少含一行非空说明，框内不得有空物理行。依据相邻结构归属，不根据说明正文推测业务含义；注释中的方法名或代码示例不得被提取为真实定义。孤立说明、未闭合框与保护标记继续保守处理，不能用完整框绕过预处理或锁定段门禁。 含 `@file`、`@mainpage`、`@page`、`SPDX-*:` 字段（兼容 `SPDX-License-Identifier`）或 `Copyright`（忽略大小写）的完整框按文件级说明处理：首函数前整框留在文件前言，函数之间则保留整文件并警告。

#### 3.1.1 文件级 pragma 折叠区

2026-10-12 第二阶段：完整配对、位于完整函数之间的 `#pragma region` / `#pragma endregion` 作为固定屏障。指令及其包住的内容逐字保留，区内函数不重排；只在屏障外各连续区间内排序，函数及所属注释不得跨区。全部方法都在锁定区时允许返回原文、无变更，不应仅因存在合法折叠区就报阻止。

只从屏蔽注释和字符串后的代码识别真实 pragma。函数内、切断函数签名或函数体、续行、混合换行或交错保护区等不能确认的边界继续保留原文并警告。区域内部的其他预处理指令、TIE/非成员代码仍接受原有安全检查，不能借折叠区绕过保护。2026-10-12 后续增量允许折叠区之外同时存在严格 TIE 注册对：将两种互不重叠的原始区间都作为固定屏障，各连续区间独立排序。若该组合下某一区间的全部完整方法又已位于完整 Wizard/clang-format 锁中、其余仅为空白或说明，则整段原样保留，不调整生成方法的业务顺序。TIE 跨入折叠区、指令切分函数及保护区交错仍保留原文并警告。Header 按第 4 节独立检查。

#### 3.1.2 文件级 TIE 注册对

2026-10-12 第三阶段：识别同名的 `#include "TIE_Interface.h"` 与 `TIE_Interface(CurrentClass);`，必须是文件级、单行单类名实参且有分号，include 与调用之间只能有空白或注释。两行及其行尾说明原位保留，不拆开、不删除，也不自动迁移到文件前部；允许用户自行放在头文件 include 之后、构造函数之前。

排序只发生在完整注册对之间。已符合成员次序的区间原样保留；注册后的普通说明若无法确认属于注册还是后续函数，就固定说明和首个完整函数，仅排序之后的函数。完整函数说明框仍按既有归属规则处理。复杂参数、名称不匹配、续行、混合换行和非文件级注册继续保守处理。允许与互不重叠的文件级 pragma 区间组合，以及下述完整函数体内条件编译组合；新增组合路径中的 TIE 自身必须位于条件组之外。此前完全位于不参与排序前言中的注册仍沿用原有输出，不自动迁移。文件前言中的条件 include 组须独立完整配对，组内仅含普通 include、空白或注释，并采用同样的有限条件语法。其他未知宏仍不属于可排序成员。

#### 3.1.3 函数体内部条件编译

2026-10-12：允许完整函数连同内部的条件组整体排序，所有指令必须位于同一个已识别的真实函数体内。不会求值、删除分支、移动单条指令或跨函数重组条件组。

- 支持配对的 `#ifdef NAME`、`#ifndef NAME`，以及条件仅为 `0`、`1`、`defined NAME` 或 `defined(NAME)` 的 `#if/#elif`；允许嵌套与可选 `#else`。
- 每一分支的 `{}()[]` 必须完整返回进入该条件组时的状态，不得关闭外层定界符；重复 else、else 后 elif、未配对边界均拒绝。
- 签名、初始化列表或函数之间的条件组不在本轮范围内。前言中的条件栈不能跨入方法区。
- 函数中的 define、undef、include、其他 pragma、副作用宏指令、物理续行和混合换行仍保守阻止；复杂条件表达式须先有独立最小用例再扩展。
- Wizard/clang-format 保护区及函数说明仍逐字保留，最终锁区比较、完整函数库存和幂等回归继续执行。

### 3.2 排序顺序

特殊成员优先，随后普通成员按名称的大小写不敏感字母序排列：

1. 默认构造；
2. 其他构造；
3. 析构；
4. 拷贝构造；
5. 移动构造；
6. 拷贝赋值 `operator=`；
7. 移动赋值 `operator=`；
8. 其他 operator；
9. 其他成员实现。

同名 overload 依赖稳定排序，保持原有相对顺序。

### 3.3 分隔线与初始化列表

- 每个输出块使用已有 `//-----` 分隔线，缺失时使用默认分隔线。
- 完整函数说明框保留两条分隔线及说明的原始长度、缩进和尾部空格，整体随函数移动，不再额外补默认线；不能借用前一说明框的闭合线。已有无分隔线函数仍遵循默认补线规则。
- `//---static---`、`//---INSIDE FUNCTION---` 等注释型分隔线不被吸收到函数块中；不得生成连续双分隔线。
- `} //-----` 这类粘连分隔线会拆为独立行。
- 构造函数初始化列表由引擎按现有兼容规则规范化；算法变更必须更新 fixture 与 golden hash。

## 4. Header 类声明排序

本算法以既有回归工程的 clang-format 风格作为主要格式兼容基线，配置解读和完整 fixture 位置见 [C++ clang-format 规则说明](./C++%20clang-format规则说明.md)。兼容的含义是排序结果无需再次格式化即可符合与成员排序有关的稳定布局；不是在 core 内重做一套 clang-format。

### 4.1 识别范围

- 处理带导出宏、`final`、继承列表的 `class` 定义。
- 逐个 `public:`、`protected:`、`private:`、`public slots:`、`protected slots:` 与 `signals:` 访问区处理。
- 声明前的 Doxygen/普通注释随声明移动；宏、嵌套声明、Doxygen group 等无法安全展开的结构保持源顺序。

### 4.2 排序顺序

在每个可安全排序的访问区内：

1. 特殊成员按 `.cpp` 的同一优先级；
2. 普通方法按大小写不敏感字母序；
3. 成员变量默认保持原位置与相对顺序；仅 `sortMembers: true` 时才按名称排序。

2026-09-27：全部运算符重载（含带空格赋值、比较、调用、下标和类型转换）归入特殊成员，位于构造/析构之后、普通方法之前。只在既有访问区内排序，不将 private/protected 运算符提升为 public，也不为整齐而新增访问标签。宏和锁定段作为排序屏障，两侧声明不得交换位置。

含编号 Doxygen（如 `/** 1. ... */`）的声明保持源序并报告 warning，避免编号语义失效。

2026-10-10：只有类体当前层级的访问标签可以切分访问区，嵌套类作为完整屏障保留。声明的顶层初始化符号出现在函数参数括号之前时，不能把初始化中的调用识别成方法；`decltype`、模板实参、数组与函数指针也不得因此变成可排序方法。默认保留数据成员的相对顺序，访问区整体重组也必须满足该不变量。显式 `virtual` / `override` 声明作为排序屏障，保留其原始相对次序；这只是 ABI 风险防护，不等于二进制兼容验收。

### 4.3 锁定段（P0）

以下成对区间整体冻结，段内生成内容、注释与字符顺序不得变化；嵌套或重叠时合并为最外层区间：

| rule id | 起止标记 | 说明 |
| --- | --- | --- |
| `clang-format` | `// clang-format off` … `// clang-format on` | LLVM 格式化忽略段 |
| `kevin-caa-wizard` | `START KEVIN CAA WIZARD SECTION` … `END KEVIN CAA WIZARD SECTION` | Kevin CAA 向导生成段 |
| `caa2-wizard` | `// CAA2 WIZARD` … `// END CAA2 WIZARD` | CAA2 向导生成段 |
| `pragma-region` | `#pragma region` … `#pragma endregion` | IDE/生成代码折叠区 |

`#pragma region VirtualFunction` 当前按通用 `pragma-region` 处理，不另行赋予特殊排序语义。

2026-09-27 的整体保护继续适用于无法证明安全的访问标签。2026-10-12 增量仅允许 `keep_markers` 模式下，完整锁区重复进入前已生效的同级访问标签（例如已处于 `public:`，锁内再次声明 `public:`）。锁内标签不切分访问区，整块作为固定屏障；保留所有访问段的原始顺序，只有屏障外的完整声明可按既有规则整理。数据成员默认原序，virtual/override 顺序和锁区字节不变。

访问权限实际切换、slots/signals 与普通访问区混淆、嵌套或跨声明/函数的锁、宏分类有歧义、一行混合多个声明、续行及混合换行仍拒绝；`merge_strip` / `off` 不借此放宽。类体包含 `#if`、`#pragma` 等预处理边界时仍保留整类。原始受保护字节是最终输出门禁，优先于类尾空行规范。此次只调整锁区外排序识别，不改变生成规则或控制区域内容，`@codegen-rules-version` 不升级。

锁定段的内部空白逐字保护，包括 Wizard 的 `//END ...` 与 `// clang-format on` 之间已有的空行。当 `// clang-format on` 是类结束标记前的最后一项时，只删除它与 `};` 之间的纯空行。

### 4.4 Kevin system-code 兼容

`kevinSystemCodeMode` 取值如下：

- `merge_strip`（显式兼容选项）：合并可兼容的 system-code 声明并移除 START/END 标记；
- `keep_markers`（默认）：整体保留标记及内部内容，不排序其中声明；
- `off`：不进行该兼容转换。

该兼容层与锁定段不同：只处理已识别的声明区，不能越过锁定段。

### 4.5 类结束标记前的空行

- Header 排序输出中，最后一个成员变量或成员函数后必须直接连接类结束标记 `};`，两者之间不得保留空行。
- 如果最后一个成员位于类尾 Wizard 锁定段内，则保留 `//END ...` 与 `// clang-format on` 之间的原始空白；`// clang-format on` 与 `};` 必须紧邻。
- 该约束同时适用于 LF 与 CRLF，并且必须保持二次执行幂等。
- 这是 KtAlarmClock clang-format 基线的稳定结果；core 应直接生成该结果，不能要求宿主在写盘后再运行 clang-format。
- 类内部有意义的单空行分组仍可保留；本规则只收敛类体末尾、结束标记之前的空白。

### 4.6 缺失函数文档

- Header 的 `addMissingFunctionComments: true` 只对已识别且缺少注释的普通方法声明或内联实现补空白 Doxygen；构造函数（含拷贝、移动）、析构函数与赋值运算符 `operator=` 始终不自动补注释，既有注释原样保留。
- 2026-10-11 用户调整：产品宿主增加独立“补全函数注释” checkbox，初始不勾选，仅作为当前会话选项。关闭时不启用 Header 注释补全，也不调用 Source 文档 API；与 include 分组独立。切换后清除旧结果和选择并要求重新扫描，旧计划与延迟事件失效。
- 生成空 `@brief`、可确定名称的 `@param`，以及非 void 的空 `@return`。不推测业务描述，不把未命名类型当成参数名；既有普通注释或 Doxygen 均保留。不会自动清除此前已写入的空注释。
- 相邻函数至少留一个空行。嵌套、编号或锁定结构仍按安全边界处理，不为补注释而展开、修改保护区。
- Source 文档 API 独立于排序：普通/匿名命名空间内可识别的自由函数可补注释；类外限定成员只有在提供头文件上下文且未发现对应声明时才补。宿主使用扫描范围内唯一同名头文件原文作为上下文，缺失或歧义时不假定不存在声明。
- 已识别的构造、析构及 `operator=` 实现直接跳过，不因缺少头文件上下文阻止其他普通函数补注释。关闭补注释时，宿主不检查仅用于文档补全的头文件内容依赖；include 分组自己的分类依赖照常检查。
- 这是保守的文本识别，不是完整 C++ AST。复杂模板、宏与预处理上下文须通过最小用例验证后再扩展；警告不能被宿主忽略。

### 4.7 可选 include 分组

分类结果的 `usedTrustedHeaders` 只列出实际发生编辑的区间使用过的精确自定义规则。Host 据此映射自动项目头的文件依赖，在确认前及逐文件写入前复核其仍存在；不复制 include 解析器。

块注释形式 `/* clang-format off */` 与带说明的 `// clang-format off: reason` 尚未纳入区间提取器，因此成员排序、函数注释和 include API 均通过共享边界检查警告并保留整文件，不能忽略这些合法保护标记。

`pnwGroupCppIncludesText(text, { sortIncludes, trustedHeaders })` 是独立纯算法；`PNW_INCLUDE_GROUPING_VERSION = 1` 标识该能力。`sortIncludes` 默认关闭，关闭时逐字返回原文。此选项不改变成员、注释或保护区的安全门禁。

启用后，在可确认类别的连续 include 区间内，按标准库、第三方、CAA SDK、项目头文件排列，组内采用稳定字典序、组间一个空行。每条原始指令的缩进、包含路径、引号/尖括号与尾随注释一起移动；不删重复项、不生成组标题、不改路径。

- 内置标准库名单固定到 C++23 N4950 的头文件表。只有名单中的尖括号形式自动识别；引号形式可能被项目同名文件遮蔽，需可信解析结果。
- `trustedHeaders` 只接受精确包含名及明确类别：`{ header, group, delimiter? }`。`delimiter` 可限制 `angle` / `quote`。Host 可依据实际项目文件建立引号形式的相对路径映射，也可传入项目明确配置；不得只按 basename、尖括号、`CAT` 前缀推断类别。
- 未知类别是原位屏障；互相冲突的分类保留原位并警告。普通未知项不等同于损坏，不产生整文件错误。
- 不跨普通代码、独立注释、非 include 预处理指令、宏 include 或续行；不得跨 `#if/#elif/#else/#endif` 分支。未配对条件或保护标记阻止全文重建。
- `TIE_*.h` 包含项固定原位，注册宏为独立屏障；Wizard、clang-format、pragma region、系统生成区整体保留。安全规则不能通过勾选分组关闭。
- 保持 BOM、换行风格和文件末尾换行约定，并要求幂等。编码的字节往返由 Host 验证。

宿主 UI 在当前排序工具内部提供默认关闭的 checkbox；切换后清空旧预览并要求重新扫描，扫描记录选项和分类配置快照。应用前、确认后及每次写入前校验计划代次与配置；旧行事件携带原扫描 revision，不能被重新解释成当前结果。缺少此能力的运行时在启用分组时阻止应用。

分类准确不等于头文件次序无依赖。专项测试和词法复测不代替目标工具链编译；现有成员排序或函数注释步骤给出安全警告时，宿主继续保留整份原文，不借 include 开关绕过它。

## 5. 宿主契约（必须遵守）

排序结果的文件行默认查看差异：待应用项打开排序前后对比，已应用项打开 Git 差异；不可查看状态不发送旧预览事件。待应用项原对比图标按钮改为“查看”原文件，提示及无障碍名称为“查看”，动作使用 `open`；与文件名点击的对比入口区分。这些操作继续携带原结果 revision，不得写盘。

| 环节 | 要求 |
| --- | --- |
| 扫描/预检 | 只计算 core 结果，默认只展示 `changed` 文件；点击文件只能打开原文件，不创建临时 `untitled` Diff。 |
| 安全门禁 | source 和 header 的警告都必须可见；存在警告、异常、`changed` 与文本不一致时保留原文并禁止写盘。旧运行时若未声明安全能力，不允许写入其变化结果。 |
| 写盘 | 必须经显式确认；写前比较当前原始字节与预检快照，不一致则阻止写入。 |
| 写盘后 | 仅更新缓存表格行状态，不重新扫描或清空用户勾选状态。不得对批量结果逐个自动弹出 Diff。 |
| 差异预览 | 只在用户点击已写盘行的“预览差异”时，调用宿主的内置 Git 查看；不实现自定义 Diff。 |
| 还原 | 仅可恢复本次会话中成功写盘的文件；恢复前比较当前字节是否仍等于本次输出，避免覆盖用户后续修改；恢复的是排序前快照，不是盲目 `git restore`。 |

### 5.1 开发人员逐项核对

2026-10-12 用户授权：已阻止项可以单独打开只读诊断，显示完整原因和扫描原文。只有运行时实际返回过不同文本时，宿主才可单独保存该候选并通过原生 Diff 对比；不得为制造差异而绕过解析保护。没有候选时说明原因，不显示虚假的排序差异。

## 6. 回归契约与已知边界

当前 core fixture 位于 `packages/code-core/src/fixtures/`；其中 `ktalarmclock.clang-format.yaml` 保存实际项目格式基线，`clang_format_class_tail.h` 锁定类尾空行行为。测试覆盖：

- `.cpp` 的 Python 历史 golden hash、特殊成员、注释分隔线、函数体内部调用、分行返回类型、CRLF、初始化列表与幂等；
- header 的访问区、特殊成员、成员变量可选排序、导出宏、嵌套锁定段、Kevin/CAA2 Wizard、通用 pragma region、Kevin system-code、Doxygen 编号警告、CRLF 与幂等。
- `fixtures/reorder-safety/` 和对应安全测试只包含匿名语法，覆盖匿名 helper、注册宏、条件编译、分行签名、嵌套类与初始化成员；原始工程快照不加入此仓库。

仍需补充最小 fixture 后再放宽的边界：

1. 带 `requires`、尾置返回类型、复杂模板实参或函数指针的类外定义；
2. 更复杂的 C++ 词法和预处理条件组合；当前覆盖常见字符串/原始字符串大括号，复杂预处理仍保守跳过；
3. 多个同名/多命名空间类实现共存的 `.cpp`；
4. 更复杂的宏声明、C++20 module、Unicode 标识符；
5. 新的 CAA Wizard 标记。

新增或调整规则时：先新增最小 fixture，再写输出/锁定字节/幂等断言；若 `.cpp` 输出有意改变，更新历史 golden hash 并在提交说明中写明原因。
