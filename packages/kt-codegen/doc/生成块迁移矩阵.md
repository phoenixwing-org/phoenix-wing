# 参数代码生成块迁移矩阵

本文把旧 VB 的32个自动代码块映射到 `KtCodegen` 的稳定 block key、主目标和迁移状态。它用于控制迁移顺序、建立 golden tests，并防止重写时遗漏或误删旧能力。

## 权威来源

- 归档基线 `KtaAutoCodeBase/KevinControlID.vb`：0～31 的旧枚举顺序；
- 归档基线 `KtaAutoCodeBase/KevinControlWords.vb`：源码标记中的稳定字符串；
- 归档基线 `KtaAutoCodeBase/KevinCAAFileGuide.vb`：`CreateCAAItem` 分派和实际生成方法；
- [`legacy-blocks.ts`](../src/blocks/legacy-blocks.ts)：TypeScript 可执行迁移元数据；
- [`analyze.test.ts`](../tests/analyze.test.ts)：数量、ID、key、旧调用、目标和状态约束。

归档标签和完整旧文件索引见[《来源与许可归档》](来源与许可归档.md)。

`legacySourceLine` 记录当前归档版本中旧方法定义的起始行，只用于人工审计；稳定身份仍是 `legacyId + key`。主目标表示新 Core/Renderer 中的职责归属，不代表旧源码所在文件。

## 建议迁移顺序

1. **普通 C++ Parameter**：10～13 已完成，用于确定换行、缩进、注释和 artifact 契约，详见[《普通 C++ 参数块迁移》](普通C++参数块迁移.md)。
2. **CAA 接口与 Feature I/O**：0～9 已完成，详见[《CAA 接口头文件块迁移》](CAA接口头文件块迁移.md)、[《CAA 特征读写块迁移》](CAA特征读写块迁移.md)和[《CAA 目录与树工厂块迁移》](CAA目录与树工厂块迁移.md)。
3. **CAA/Qt 对话框联动**：14～18 已完成，详见[《CAA 对话框通知块迁移》](CAA对话框通知块迁移.md)和[《CAA 与 Qt 对话框双向更新块迁移》](CAA与Qt对话框双向更新块迁移.md)。
4. **Dialog Selector 能力**：19～21 已完成，详见[《Dialog 字段与废弃兼容块迁移》](Dialog字段与废弃兼容块迁移.md)。
5. **Command Agent 生命周期**：22～24 已完成，详见[《Command Agent 生命周期块迁移》](CommandAgent生命周期块迁移.md)。
6. **Command Graph 与 State**：25～27 已完成，详见[《Command 图与状态块迁移》](Command图与状态块迁移.md)。
7. **Command Action 与活动 Field**：28～31 已完成，详见[《Command 动作与活动字段块迁移》](Command动作与活动字段块迁移.md)。
8. **废弃块策略**：20、21、30 均按兼容输出迁移，实际生成时发出 warning；三项都保留稳定 key 和解析能力，不得静默删除。

## 状态维护条件

矩阵中的“已迁移”必须同时满足：旧生成方法已审计、Renderer 已实现、golden 已建立、Analyze artifact 已关联安全标记区域。不能因已有相似功能而直接批量改状态。

- 32个 ID 连续且不重复；
- 32个 key 不重复；
- 每项都有可定位的旧 VB 调用和源码行；
- 每项都有新主目标；
- 旧代码明确废弃的三项被单独标记；
- 测试对以上规则形成自动约束；
- 当前 ID 0～31 全部标记为已迁移，其中 ID 20、21、30 明确保留废弃兼容状态。
